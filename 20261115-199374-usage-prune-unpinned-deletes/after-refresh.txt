# Usage refresh after deleting 100 of 5000 transcripts (24 months each), three runs, after the fix.
# Each run: build the cache with a real refresh, set the cache_entries planner statistics to the
# ones SQLite's own PRAGMA optimize writes for a one-row table (the driver edits sqlite_stat1
# directly to simulate a cache that held one row when statistics were last written), delete
# 100 transcripts, then run one real refresh with a foreground writer probe every 10 ms.
# Refresh JSON fields: pruneWriterHoldMs = the prune transaction's writer hold;
#   overlapProbeWaitMs = waits of probes started while the prune transaction held the writer;
#   foregroundWriterWaitMs = waits of all probes during the whole refresh;
#   writerPhases = every refresh writer hold, grouped by worker operation.
# plans-summary.txt shortens statement text: bind lists collapsed to (...), the OR chain of the
#   rollup batch delete replaced by (OR ...), each statement cut at 110 characters. The full
#   statements and plans are in each run's plans.jsonl, kept with the proof logs.
# Environment lines, identical on both sides: "log file append failed" comes from the proof
#   environment's file-log target; "integrity gate ... reason=file-mismatch" and
#   "clean-close receipt: verification-missing" follow the driver's direct sqlite_stat1 edit
#   outside OpenClaw; the other "clean-close receipt" lines are written when the driver process
#   closes the database at exit.
